# How to reproduce Simulation S1

Everything in the response to Reviewer 1, in Supplement S1 and in Discussion 4.4 is
regenerated by the scripts in this folder from two sets of raw inputs. Nothing is
hard-coded: every observed number is recomputed from the spider CSVs each time a
script runs.

**The simulation is deterministic.** Individual clocks are drawn at random, but from
fixed seeds (`np.random.default_rng(20260909)` in step A, `default_rng(20260910)` in
step C), so a rerun on the same 500 individuals reproduces the published numbers to
the last digit, not approximately. `verify_reproduction.py` checks 55 of them and
prints a pass/fail table. If a number moves, something really has changed.

---

## 1. What you need

Python 3.9 or newer with **numpy, scipy, pandas, matplotlib**. A standard Anaconda
install already has all four. `astropy` is optional: it is used by one cross-check
(test T6, which confirms the fast periodogram in the code agrees with astropy's
Lomb-Scargle). Without it the simulation runs and prints `T6 SKIPPED`. To add it:

```
conda install astropy
```

Inputs, already in this folder and not regenerated:

| folder | contents | where they came from |
|---|---|---|
| `spider_data\` | the three `*_comprehensive_with_LD_split.csv` period files and the three `*_circular_stats_v2.csv` files | this is our spider data pipeline; the circular-stats files are the source of the 91 / 63 / 48 figures in Figure 1D–F |
| `spider_profiles\` | the six `*_aligned_activity.csv` 24 h profiles | `original figures\Figure 3 hourly over cycle profiles\` |

## 2. The quick way: one file

Open **`RUN_ALL.py`** in Spyder and press **F5**. It runs every stage in order, in
the right folders, and finishes by checking the results against the published ones.
Expect **about 35 minutes**; the console prints a timing line after each stage.

Two switches at the top of the file:

- `QUICK_TEST = True` uses 40 individuals per species instead of 500. The whole
  pipeline then takes about 3 minutes. Use it once to confirm everything runs, then
  set it back to `False`. With 40 individuals the percentages will be a few points
  off the published ones and `verify_reproduction.py` will report differences, which
  is expected.
- `REBUILD_LIBRARY = False` skips the 3-minute step A and reuses the `dd_library.csv`
  already in the folder. Leave it `True` for a genuine from-scratch reproduction.

If you would rather watch it stage by stage, `RUN_ALL.py` is split into Spyder cells;
step through with **Ctrl+Enter**.

Step 5 is the one that needs care, because it runs **inside the track folder**, not
here. `RUN_ALL.py` does this for you; by hand it is:

1. copy `s1d_beta_sweep.py` into `track1_main\`
2. copy `population.csv` into `track1_main\`
3. open `track1_main\s1d_beta_sweep.py` in Spyder and run it (F5)

The track folder is just a working directory: `s1d_beta_sweep.py` reads the
`population.csv` sitting beside it and writes its results beside itself.

## 4. What "verified" looks like

`verify_reproduction.py` recomputes 55 quantities and compares them with
`reference_values.csv`, which holds the values behind the submitted text. It covers

- the observed numbers (these use only the spider CSVs, so they must match exactly
  on any machine): 90.6 / 63.4 / 48.4 % entrained, the decomposition 91/88/71 % with
  a significant rhythm, the DD rhythmic fractions and free-running periods;
- the three fitted population parameters per species;
- % rhythmic in DD, % entrained and % phase-locked at the published β, per species;
- the *S. grossa* β curve at 0, 0.75 and 2.0, and that it is monotonic;
- the manuscript-scale numbers quoted in the response (70 / 23 / 64 %) and the β
  values that would be needed to match observation (≈ 0.27, > 1.4, ≈ 0.26).

A clean run prints `REPRODUCED` and every difference is 0.

## 6. Two scales for β, and why the numbers differ between documents

The manuscript defines I(t) = 1 during the light phase, so its β is the fractional
rise in k₂ when the lights are on. The simulation code inherited `lux = 700` from
`beta_LD_sweep.py`, so it uses I = 0.7 and its β is 1/0.7 times larger for the same
physical effect.

- `S1_RESULTS_09102026.md` and everything under `track1_main\` are on the
  **simulation** scale (β = 0.09 / 0.06 / 0.75 as typed in the code, giving 64 / 21 / 60 %).
- The response letter, Supplement S1 and `s1g_supplement_figures.py` are on the
  **manuscript** scale (β_manuscript = 0.7 × β_simulation, giving 70 / 23 / 64 %).

Same runs, same model, one rescaling of the x-axis. `verify_reproduction.py` checks
both.

## 7. Independent check already on file

`verify\` holds a check made without reusing any of the pipeline code: it recomputes
the headline percentages straight from `results_individual.csv`, and re-simulates
four individual *S. grossa* from scratch with `scipy.integrate.odeint`, integrating
each light and dark segment separately. All four entrainment calls and every period
agreed to 0.001 h. `verify\verification_report.md` has the detail.

---

## 8. If something goes wrong

- **`ModuleNotFoundError: astropy`** — harmless, the simulation does not need it.
- **`FileNotFoundError: population.csv`** inside a track folder — step 6 was started
  before the population file was copied in. Use `RUN_ALL.py`, or copy it by hand.
- **Assertion error in the test suite** — one of T1 to T6 failed, which means the
  model is not behaving as it should (for example β is no longer inert in darkness).
  The failing test name is printed; do not trust any result from that run.
- **The run is slower than 35 minutes** — normal on a busy laptop. The cost is
  dominated by step 6, which integrates 500 individuals × 12 β values × about 47
  simulated days at a 0.01 h step, twice over.
